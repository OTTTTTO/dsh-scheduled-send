# Doublecheck spec

## Goal
交付独立 DSH 插件 dsh-scheduled-send（git 仓库 /home/otto/repos/dsh-scheduled-send）：⏰按钮位于输入框底部与发送并排，打字后点⏰弹出时间确认（默认当前+5分钟）转为定时任务，支持多条任务（升序+折叠+取消+指定模型：到点先切模型再发），到点后消息以正常用户气泡出现在当前会话聊天流（硬验收），已排程即时显示且等宽保留源文格式；同时从 glm-coding-plan-guard 移除定时能力避免重复注入；市场发布留待本地验收后另行确认。

## Scope
新建 /home/otto/repos/dsh-scheduled-send（git init、README、npm 包结构、宿主侧 scheduler+delivery+schedule/cancel 路由、客户端 composer ⏰按钮+时间确认+已排程列表）；修改 glm-coding-plan-guard 仅限移除定时相关模块/路由/UI 并保其测试绿；需调研 DSH composer 按钮挂载点与真实可见注入 API。不含：发布 npm/市场（另阶段）、重复规则任务、跨会话目标选择。

## Acceptance criteria
1) ⏰按钮出现在输入框底部与发送按钮并排（composer 挂载点）；2) 打字后点⏰弹时间选择，默认当前+5分钟可改，确认后内容转为任务、输入框清空、不立即发送；3) 已排程条目在输入框上方即时出现（无需刷新），多条按时间升序、>3条折叠可展开，每条含内容、计划时间、倒计时、取消按钮；4) 内容以等宽字体完整保留源文（换行/缩进/Markdown 源码）；5) 指定模型：创建时可选，到点先切会话模型再发送；6) 到点后消息以正常用户气泡出现在当前会话聊天流且触发模型响应（真实环境人工验收）；7) 发送目标绑定创建时的当前会话，dsh 重启后补发仍到该会话；8) glm-coding-plan-guard 移除定时能力后其额度/峰时/提醒/视觉路由测试全绿；9) 两插件同时安装无重复注入；10) 新插件全量测试 0 失败。

## Failure modes
composer 挂载点或可见注入 API 不存在：调研后采用最接近方案并在 README 标注限制，不静默假装满足；创建时无活跃会话：拒绝创建并提示；切模型失败：降级按当前模型发送并提示；提交网络失败：表单保留；多条任务某条投递失败：其余不受影响（既有语义）；新插件未装而旧插件已移除定时：无定时能力属预期。

## Priorities
到点消息真实可见（#4）> 即时显示与交互正确 > 列表展示形态 > 装饰；两插件不重复注入红线优先于功能丰富度。

## Non-goals
本次不发布 npm/插件市场；不做重复规则（每日等）、不做目标会话选择器、不做系统通知；不改 DSH 核心源码。
